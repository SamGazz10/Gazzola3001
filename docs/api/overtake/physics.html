overtake.physics

Straight-line dynamics of two 2026 F1 cars running nose to tail.

The closing stage of an overtaking attempt is an initial value problem. Each car has position x (m), speed v (m/s) and electrical energy used e (J), and obeys

dx/dt = v
m dv/dt = min(F_power, F_traction) - F_drag - F_rolling
de/dt = P_ers

where

  • F_power = eta (P_ice + P_ers) / v is the drive force the power unit can supply. P_ers is the MGU-K power, limited by the 2026 speed taper, by Boost / Overtake Mode, and by the energy left in the battery.
  • F_traction = mu * w_r * (m g + 1/2 rho ClA v^2) is the most the driven rear tyres can transmit. For a new soft tyre (mu = 1.7) this, not power, limits acceleration below about 180 km/h on the standard energy map (about 200 km/h with Boost, and higher on tyres with less grip), which is how tyre grip enters the model.
  • F_drag = 1/2 rho CdA v^2. The following car's CdA is reduced by the slipstream, which decays with the distance between the cars.
  • F_rolling = c_rr (m g + 1/2 rho ClA v^2).

The two cars are coupled through the slipstream, so both are integrated together. Integration starts as both cars exit the corner before the run and stops when the defender reaches the braking point at the end of the run. The result is how far (in seconds) the attacker is still behind at that moment.

Two explicit fixed-step methods are provided: forward Euler (first order, used as a baseline) and classical Runge-Kutta (RK4, fourth order, used by the simulator). Both are verified against analytical solutions in tests/test_physics.py and overtake.experiments.solver. On the full model the kinks (traction limit, MGU-K taper, energy running out) lower RK4's observed order to about 2 (overtake.experiments.timestep).

Parameter values are approximate public figures for 2026 cars or engineering estimates; they are collected in CarParameters so they can be changed.

124def mguk_power_limit(speed, overtake_mode, car=CarParameters()):
125    """Maximum MGU-K power allowed by the 2026 regulations at a given speed.
126
127    Full power up to 290 km/h (337 km/h with Overtake Mode), falling linearly
128    to zero at 355 km/h (`TAPER_STANDARD_KPH`, `TAPER_OVERTAKE_MODE_KPH`).
129
130    Parameters
131    ----------
132    speed : array_like
133        Car speed in m/s.
134    overtake_mode : array_like of bool
135        Whether Overtake Mode is active, which delays the taper. Broadcast
136        against ``speed``.
137    car : CarParameters, optional
138        Supplies the maximum, ``car.mguk_power_w`` (350 kW by default).
139
140    Returns
141    -------
142    numpy.ndarray
143        Power limit in W, between 0 and ``car.mguk_power_w``, with the
144        broadcast shape of ``speed`` and ``overtake_mode`` (a NumPy scalar
145        when both are scalars).
146
147    Examples
148    --------
149    >>> mguk_power_limit(np.array([250.0, 322.5, 355.0]) / 3.6, False)
150    array([350000., 175000.,      0.])
151    """
152    kph = np.asarray(speed) * 3.6  # the rules state the taper in km/h
153    start = np.where(overtake_mode, TAPER_OVERTAKE_MODE_KPH[0], TAPER_STANDARD_KPH[0])
154    end = TAPER_STANDARD_KPH[1]  # both modes reach zero at the same speed
155    return car.mguk_power_w * np.clip((end - kph) / (end - start), 0.0, 1.0)

208def acceleration(speed, energy_used, state, cda_m2, car=CarParameters()):
209    """Longitudinal acceleration and MGU-K power draw of one car.
210
211    Evaluates ``m dv/dt = min(F_power, F_traction) - F_drag - F_rolling`` (see
212    the module docstring) for every scenario at once.
213
214    Parameters
215    ----------
216    speed : numpy.ndarray
217        m/s. Values below 1 m/s are treated as 1 m/s to avoid dividing by zero.
218    energy_used : numpy.ndarray
219        Electrical energy used so far on this run, J.
220    state : CarState
221        The car's settings (tyre grip, deployment, energy available).
222    cda_m2 : numpy.ndarray
223        Drag area to use, m^2, i.e. ``state.cda_m2`` already reduced by any slipstream.
224    car : CarParameters, optional
225        Constants shared by both cars.
226
227    Returns
228    -------
229    accel : numpy.ndarray
230        m/s^2.
231    ers_power : numpy.ndarray
232        MGU-K power actually drawn from the battery, W, i.e. ``de/dt``.
233    """
234    v = np.maximum(speed, 1.0)
235    # Share of the MGU-K power still allowed: 1 until the last energy_smoothing_j of the energy
236    # available, then falling linearly to 0 as the energy runs out (see CarParameters).
237    remaining = np.clip((state.energy_j - energy_used) / car.energy_smoothing_j, 0.0, 1.0)
238    ers_available = state.deploy_share * mguk_power_limit(v, state.overtake_mode, car) * remaining
239
240    # Downforce adds to the tyres' vertical load, raising both grip and rolling resistance.
241    downforce = 0.5 * car.air_density * car.cla_m2 * v**2
242    normal_load = car.mass_kg * GRAVITY + downforce
243    f_power = car.drivetrain_efficiency * (car.ice_power_w + ers_available) / v
244    f_traction = state.mu * car.driven_axle_share * normal_load
245    f_drive = np.minimum(f_power, f_traction)
246
247    # When traction-limited the driver uses less power; the engine supplies
248    # first and the MGU-K only the remainder. When power-limited this gives
249    # back ers_available, so the upper clip only absorbs round-off.
250    power_used = f_drive * v / car.drivetrain_efficiency
251    ers_power = np.clip(power_used - car.ice_power_w, 0.0, ers_available)
252
253    f_drag = 0.5 * car.air_density * cda_m2 * v**2
254    f_rolling = car.rolling_coeff * normal_load
255    return (f_drive - f_drag - f_rolling) / car.mass_kg, ers_power

258def slipstream_factor(separation_m, car=CarParameters()):
259    """Multiplier (<= 1) on the following car's drag area.
260
261    Parameters
262    ----------
263    separation_m : numpy.ndarray
264        Position of the car ahead minus position of the follower, m. Zero
265        when the cars are level, negative once the follower is in front.
266    car : CarParameters, optional
267        Supplies ``tow_max``, ``tow_length_m`` and ``car_length_m``.
268
269    Returns
270    -------
271    numpy.ndarray
272        ``1 - tow_max * exp(-separation / tow_length)`` while the follower is
273        behind or level, fading linearly to 1 as it moves from level to one
274        car length in front. Lies between ``1 - tow_max`` (0.75 by default,
275        when level) and 1.
276    """
277    sep = np.asarray(separation_m)
278    # Both branches equal 1 at sep = 0, so the factor is continuous. np.where evaluates both for every
279    # entry, so the exponential sees sep clipped at 0 and cannot overflow for a follower far ahead.
280    behind = np.exp(-np.maximum(sep, 0.0) / car.tow_length_m)
281    alongside = np.clip(1.0 + sep / car.car_length_m, 0.0, 1.0)
282    return 1.0 - car.tow_max * np.where(sep >= 0, behind, alongside)

285def two_car_rhs(y, attacker, defender, car=CarParameters()):
286    """Right-hand side of the coupled two-car system.
287
288    Only the attacker gets a slipstream (from the defender ahead); the
289    defender's drag is never reduced, even if the attacker draws ahead.
290
291    Parameters
292    ----------
293    y : numpy.ndarray, shape (6, n)
294        Rows are attacker position (m), speed (m/s) and energy used (J), then
295        the same for the defender; one column per scenario.
296    attacker, defender : CarState
297        Settings of each car, one entry per scenario.
298    car : CarParameters, optional
299        Constants shared by both cars.
300
301    Returns
302    -------
303    numpy.ndarray, shape (6, n)
304        Time derivatives of ``y``: speed, acceleration and MGU-K power of the
305        attacker, then of the defender.
306    """
307    xa, va, ea, xd, vd, ed = y
308    acc_a, ers_a = acceleration(va, ea, attacker, attacker.cda_m2 * slipstream_factor(xd - xa, car), car)
309    acc_d, ers_d = acceleration(vd, ed, defender, defender.cda_m2, car)
310    return np.stack([va, acc_a, ers_a, vd, acc_d, ers_d])

313def euler_step(f, y, dt):
314    """One forward Euler step of ``dy/dt = f(y)``. First order: global error O(dt).
315
316    Parameters
317    ----------
318    f : callable
319        Maps the state array to its time derivative (same shape).
320    y : numpy.ndarray
321        State at the start of the step.
322    dt : float
323        Step size, s.
324
325    Returns
326    -------
327    numpy.ndarray
328        State at the end of the step.
329    """
330    return y + dt * f(y)

333def rk4_step(f, y, dt):
334    """One classical Runge-Kutta step of ``dy/dt = f(y)``. Fourth order: global error O(dt^4).
335
336    The order holds for a smooth ``f``; each step costs four evaluations of ``f``.
337
338    Parameters
339    ----------
340    f : callable
341        Maps the state array to its time derivative (same shape).
342    y : numpy.ndarray
343        State at the start of the step.
344    dt : float
345        Step size, s.
346
347    Returns
348    -------
349    numpy.ndarray
350        State at the end of the step.
351    """
352    # Slopes at the start, twice at the midpoint and at the end, combined with Simpson weights 1-2-2-1.
353    k1 = f(y)
354    k2 = f(y + 0.5 * dt * k1)
355    k3 = f(y + 0.5 * dt * k2)
356    k4 = f(y + dt * k3)
357    return y + dt / 6.0 * (k1 + 2 * k2 + 2 * k3 + k4)

364def integrate(f, y0, dt, n_steps, method="rk4"):
365    """Integrate an autonomous system ``dy/dt = f(y)`` with fixed steps.
366
367    Parameters
368    ----------
369    f : callable
370        Maps the state array to its time derivative (same shape).
371    y0 : array_like
372        Initial state. It is copied to a float array, so the input is not modified.
373    dt : float
374        Step size, s.
375    n_steps : int
376        Number of steps.
377    method : {"rk4", "euler"}, optional
378        Step function from `STEPPERS`.
379
380    Returns
381    -------
382    numpy.ndarray
383        State after ``n_steps * dt`` seconds.
384
385    Raises
386    ------
387    KeyError
388        If ``method`` is not "rk4" or "euler".
389    """
390    step = STEPPERS[method]
391    y = np.array(y0, dtype=float)
392    for _ in range(n_steps):
393        y = step(f, y, dt)
394    return y

397def _hermite(p0, m0, p1, m1, s, dt):
398    """Cubic Hermite interpolant at fraction ``s`` in [0, 1] of a step of length ``dt``.
399
400    ``p0`` and ``p1`` are the values and ``m0`` and ``m1`` the time derivatives
401    at the two ends of the step.
402    """
403    # Hermite basis on [0, 1]; the derivative terms are multiplied by dt because s = t / dt.
404    h00 = 2 * s**3 - 3 * s**2 + 1
405    h10 = s**3 - 2 * s**2 + s
406    h01 = -2 * s**3 + 3 * s**2
407    h11 = s**3 - s**2
408    return h00 * p0 + h10 * dt * m0 + h01 * p1 + h11 * dt * m1

411def _crossing_fraction(x0, v0, x1, v1, target, dt, iterations=4):
412    """Fraction of the step at which the Hermite cubic through (x0, v0), (x1, v1) reaches ``target``.
413
414    Starts from linear interpolation and refines with a fixed number of Newton
415    iterations (no tolerance test). On the random steps of
416    ``tests/test_physics.py`` two iterations already reach round-off (about
417    3e-13 m), so the default of four leaves a margin. Hermite interpolation is
418    fourth-order accurate, matching RK4.
419    """
420    # Linear first guess; the 1e-12 m floor avoids dividing by zero if the car did not move.
421    s = np.clip((target - x0) / np.maximum(x1 - x0, 1e-12), 0.0, 1.0)
422    for _ in range(iterations):
423        value = _hermite(x0, v0, x1, v1, s, dt) - target
424        # d/ds of the interpolant: the derivatives of the four basis functions in _hermite.
425        slope = (6 * s**2 - 6 * s) * x0 + (3 * s**2 - 4 * s + 1) * dt * v0 \
426            + (-6 * s**2 + 6 * s) * x1 + (3 * s**2 - 2 * s) * dt * v1
427        # Newton update, guarded against a zero slope and kept inside the step.
428        s = np.clip(s - value / np.where(np.abs(slope) > 1e-12, slope, 1e-12), 0.0, 1.0)
429    return s

463def run_to_braking_point(run_length_m, gap_s, attacker_speed0, defender_speed0, attacker, defender,
464                         car=CarParameters(), dt=0.05, method="rk4", max_time_s=60.0, crossing="hermite"):
465    """Integrate both cars from the corner exit until the defender reaches the braking point.
466
467    All scenarios are integrated together as NumPy arrays. Scenarios drop out
468    of the active set as soon as their defender crosses the braking point; the
469    exact crossing time within the last step is found by Hermite interpolation.
470
471    Parameters
472    ----------
473    run_length_m : array_like, shape (n,)
474        Distance from the corner exit to the braking point, m. Must be > 0.
475    gap_s : array_like, shape (n,)
476        Time gap at the corner exit, s. The attacker starts ``gap_s *
477        defender_speed0`` metres behind.
478    attacker_speed0, defender_speed0 : array_like, shape (n,)
479        Corner-exit speeds, m/s.
480    attacker, defender : CarState
481        Settings of each car, one entry per scenario.
482    car : CarParameters, optional
483        Constants shared by both cars.
484    dt : float, optional
485        Time step, s. At 0.05 s the worst deficit error over 2000 random
486        scenarios is about 0.06 ms against a 0.001 s reference, well inside
487        the 1 ms limit (`overtake.experiments.timestep`), and the step is
488        about three times smaller than RK4's stability limit
489        (`overtake.experiments.stability`).
490    method : {"rk4", "euler"}, optional
491        Step function from `STEPPERS`.
492    max_time_s : float, optional
493        Safety limit, s; a RuntimeError is raised if a defender has not
494        reached the braking point by then (e.g. a non-physical input left it
495        stationary).
496    crossing : {"hermite", "linear"}, optional
497        How the state at the braking point is found within the last step:
498        cubic Hermite interpolation with a Newton solve (fourth order, the
499        default) or straight-line interpolation (second order; kept only so
500        that `overtake.experiments.timestep` can measure the difference).
501
502    Returns

510        If ``crossing`` is not "hermite" or "linear".
511    KeyError
512        If ``method`` is not "rk4" or "euler".

514        If any scenario is still running after ``max_time_s``.

534    n = length.size

536    # time gap times the defender's speed behind it, and neither has used any energy yet.
537    y = np.stack([
538        -np.asarray(gap_s, dtype=float) * defender_speed0,
539        np.asarray(attacker_speed0, dtype=float),

543        np.zeros(n),
544    ])

546    finish_time = np.full(n, np.nan)

548    active = np.arange(n)
549    att, dfd, target = attacker, defender, length
550    step = STEPPERS[method]
551    t, steps = 0.0, 0
552
553    def f(state):
554        """Right-hand side for the active scenarios, using ``att`` and ``dfd`` as last rebound in the loop."""
555        return two_car_rhs(state, att, dfd, car)
556
557    while active.size:
558        if t > max_time_s:
559            raise RuntimeError(f"{active.size} scenario(s) did not reach the braking point in {max_time_s} s")
560        y_new = step(f, y, dt)
561        crossed = y_new[3] >= target  # the run ends when the defender reaches the braking point
562        if crossed.any():
563            idx = active[crossed]  # columns of the finishing scenarios in the full-size outputs
564            if crossing == "linear":

566                s = np.clip((target[crossed] - y[3, crossed]) / np.maximum(y_new[3, crossed] - y[3, crossed], 1e-12),
567                            0.0, 1.0)
568                final[:, idx] = y[:, crossed] + s * (y_new[:, crossed] - y[:, crossed])
569            else:

571                # fourth-order accurate, matching RK4. The fraction s is solved on the
572                # defender's position, then used to interpolate all six states.
573                att_x, dfd_x = att.take(crossed), dfd.take(crossed)
574                d_old = two_car_rhs(y[:, crossed], att_x, dfd_x, car)
575                d_new = two_car_rhs(y_new[:, crossed], att_x, dfd_x, car)
576                s = _crossing_fraction(y[3, crossed], y[4, crossed], y_new[3, crossed], y_new[4, crossed],
577                                       target[crossed], dt)
578                for row in range(6):
579                    final[row, idx] = _hermite(y[row, crossed], d_old[row], y_new[row, crossed], d_new[row], s, dt)
580            finish_time[idx] = t + s * dt
581            # Drop finished scenarios so later steps integrate only those still running.
582            keep = ~crossed
583            active, y_new, target = active[keep], y_new[:, keep], target[keep]
584            att, dfd = att.take(keep), dfd.take(keep)
585        y = y_new
586        t += dt
587        steps += 1

590    return RunResult(

592        attacker_speed=va,
593        defender_speed=vd,
594        attacker_energy_j=ea,
595        defender_energy_j=ed,
596        time_s=finish_time,
597        steps=steps,
598    )
